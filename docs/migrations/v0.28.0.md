# Upgrading to kvn-tui v0.28.0

[Back to upgrading guide](../upgrading.md)

Version 0.28.0 hardens configuration storage, subscription downloads, daemon
IPC, and the optional privileged integrations. The `profiles.json` migration is
automatic, but existing polkit and kill-switch installations must be refreshed
manually.

## Upgrade the package

1. Upgrade kvn-tui through your usual package source.

2. Confirm that version 0.28.0 or newer is installed:

   ```bash
   kvn-tui --version
   ```

3. Open the TUI once. If an older daemon is still running, the new client stops
   it, starts the matching daemon, and reconnects the previously active profile
   when possible. A brief VPN interruption is expected during this restart.

## Refresh privileged integrations

Version 0.28.0 replaces the shared `network` group with a dedicated `kvn-tui`
group. It also narrows the polkit rule to the three required systemd-resolved
actions and installs a root-owned validating helper for the kill switch. A
package upgrade cannot safely make these system changes on its own.

Re-run setup for each integration that you use. They may be refreshed together:

```bash
sudo kvn-tui setup --polkit --killswitch
```

Or refresh only the installed integration:

```bash
sudo kvn-tui setup --polkit
sudo kvn-tui setup --killswitch
```

Run these commands through `sudo` from your regular user account. Running them
unprivileged or directly from a root shell is rejected. If setup adds your user
to the `kvn-tui` group, log out and back in, then restart the daemon:

```bash
systemctl --user restart kvn-tui.service
```

Existing membership in `network` is deliberately preserved because another
application may use it. Remove that membership manually only after checking
that it is no longer needed.

Verify the refreshed authorization and runtime dependencies as your regular
user:

```bash
kvn-tui doctor
```

If an integration is no longer wanted, remove it through the matching cleanup
command instead of deleting its files manually:

```bash
sudo kvn-tui clean --polkit
sudo kvn-tui clean --killswitch
```

## Configuration migration

The first load upgrades `profiles.json` from schema v4 to v5 and saves the
migrated file atomically. Profiles, subscriptions, DNS settings, and routing
preferences are preserved. The migration makes these settings explicit:

- `settings.tun_interface` is reset to the new default, `kvn0`;
- `settings.connectivity_probe` keeps manual `t` / `T` latency tests enabled
  with the default HTTPS endpoint;
- `settings.allow_insecure_http_subscriptions` is set to `true` for an upgraded
  configuration so existing HTTP subscriptions continue to work temporarily.

If you previously selected a custom TUN interface, inspect `profiles.json`
after the first v0.28.0 start and restore it if necessary. With the kvn-tui kill
switch enabled, use a name beginning with `kvn` so the nftables rules allow its
traffic. The legacy `tun` prefix remains supported temporarily for backward
compatibility, but this exception will be removed in a future release.

### Move HTTP subscriptions to HTTPS

Fresh v0.28.0 configurations reject plaintext HTTP subscription URLs. Upgraded
v4 configurations retain compatibility and log a warning on every HTTP update.
Move each subscription to an HTTPS endpoint, then disable the compatibility
setting in `profiles.json`:

```json
"allow_insecure_http_subscriptions": false
```

Do not disable the setting until every required subscription URL uses HTTPS;
otherwise those subscriptions are rejected before a network request is made.

The connectivity probe is used only by manual latency tests. It can be changed
or disabled independently:

```json
"connectivity_probe": {
  "enabled": false,
  "url": "https://connectivitycheck.gstatic.com/generate_204"
}
```

## Runtime directory requirement

kvn-tui now requires `XDG_RUNTIME_DIR` and stores its generated sing-box
configuration in a private `$XDG_RUNTIME_DIR/kvn-tui/` directory. It no longer
falls back to the cache directory or shared `/tmp` paths. Normal graphical user
sessions and the packaged systemd user service provide this variable. If
`kvn-tui doctor` reports that the IPC path is unavailable, run kvn-tui from the
desktop user session instead of a root shell, cron job, or bare environment.

## Configuration recovery

Configuration saves and editor changes are now conflict-safe. If the editor
and daemon change the same value concurrently, kvn-tui rejects the conflicting
write and preserves the edited version under:

```text
~/.config/kvn-tui/recovery/
```

To install a preserved configuration, stop the daemon and use the recovery
command. The current file is archived before replacement:

```bash
systemctl --user stop kvn-tui.service
kvn-tui config recover /path/to/saved-config.json
systemctl --user start kvn-tui.service
```

If `profiles.json` cannot be repaired, create a default configuration while
preserving the current file in the same recovery directory:

```bash
systemctl --user stop kvn-tui.service
kvn-tui config reset
systemctl --user start kvn-tui.service
```

Users upgrading across several releases should also follow any intervening
guides listed in the [upgrading index](../upgrading.md), especially the v0.27.0
Omarchy 4 plugin migration.
